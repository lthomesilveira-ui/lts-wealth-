# V347 — Preserve documentary identity when correcting historical expense signs

Some historical imports turn a negative workbook expense into a positive amount. These are compensations, supported by the original workbook and an already registered cash-sign proof. The existing documentary amount override mechanism can correct the consumption sign without changing the original import or its cash effect.

A rollback trial exposed a separate identity problem: correcting the amount caused the original workbook identity to stop matching because its amount still described the positive imported record. The category, source and date had not changed. V347 retains that identity only for an explicit original-to-signed documentary mapping in this batch. Source, date, original amount, signed amount, workbook identity and current category still have to match. Existing documentary overrides keep their precedence; no generic absolute-value matching is introduced.

The service-side activation script accepts a transaction-local owner and proof manifest. It requires each original import, immutable existing cash-sign proof, original workbook hash/row, description/date/bank and current effective expense to match. It rejects duplicate origins and any existing override rather than overwriting it. It inserts the established documentary corrections and updates only their existing derived cache amounts and coverage. Full before/after checks preserve all other financial fields, raw imports, dates, classifications and row counts, and verify the exact signed total change. Financial and private proof data are excluded from this repository.

Native PostgreSQL tests reproduce the identity loss, verify the fix, exercise rejected source/proof changes, preserve another owner's records and reject replay. The actual private batch must still be tried in a rollback transaction and verified before committing. This is a backend correction; the existing immutable V346 interface already supports negative expense records and remains the user-facing release.

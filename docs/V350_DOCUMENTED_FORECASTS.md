# Documented one-occurrence forecasts

Apply a private, owner-scoped manifest through the existing financial events and legacy replacement rules. Each cancellation/replacement is restricted to one exact source row, bank, description and date. Bank schedules require the original pending transaction, raw hash and account; they remain projections. Net payroll is explicitly labelled as net, so the existing operational withholding reader cannot subtract the same payroll retention twice.

Reject stale sources, existing events/rules, duplicate memberships, widened date scopes and replay. Compare every unaffected flow row, raw legacy data and realized spending before/after; assert that each new event reaches the operational reader with its exact amount and date. No published frontend is changed.

The native fixture uses the actual operational and payroll withholding functions with synthetic source data. Live rollback, activation and app-consumer checks remain separate requirements. Private photos, personal amounts and activation manifests never enter the repository.

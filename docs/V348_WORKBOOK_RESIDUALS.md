# Remaining historical workbook signs

Some historical imports turned negative expense compensations into positive consumption. The original and compacted workbooks agree on their exact ledger date, description, signed amount, category and source row. Source identity preserves description case: a similarly named positive payment must not be substituted for the negative row.

The service batch reuses documentary amount overrides and the V347 identity mapping. A private manifest must include both immutable workbook fingerprints and the exact current raw payload. The batch rejects changed source membership, existing overrides, repeated origins, later owner decisions or disagreement between workbooks. Full before/after comparisons preserve every expense attribute other than the proved amount and coverage, as well as raw imports and unrelated cache rows. No cash-sign evidence is fabricated.

A separate negative salary adjustment belongs to the workbook income row. It is excluded from spending through the established V343 documentary rule, rather than converted into a negative expense. Both source proofs, the original negative-import marker and income-row provenance are required. The original cash import remains intact. The view migration has an exact source lease; replay requires inspection instead of blind reapplication.

Native PostgreSQL contracts rerun the V343 defenses and test rejection cases, identity preservation, owner isolation, exact cache changes, private access and replay rejection. Private activation and post-commit verification remain required. The browser continues using the published V346 interface; no published frontend asset is edited.

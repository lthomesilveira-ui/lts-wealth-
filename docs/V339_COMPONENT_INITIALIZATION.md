# V339 — late component initialization

The application has bounded component installers. If a prerequisite finishes after these windows, its consumers can stay absent until a page reload. V339 keeps the existing installer windows and adds a shared readiness coordinator for 32 idempotent local installers after the cash layer.

The coordinator observes only direct additions in the app frame's head. A new runtime insertion gives waiting consumers another bounded opportunity to initialize. It stops observing when every registration is ready or exhausted, and resets its document epoch on a real frame replacement. There is no timer polling, network operation, authentication storage or financial writer in the coordinator.

Four initializer wrappers expose their existing guarded installation as a boolean operation. Every financial runtime body remains byte-identical to V337; the other 28 scripts only register their existing installer. Current balances, categories, projected payments, monthly arithmetic, authenticated readers, queue limits and execution deadlines are unchanged. Earlier published releases remain immutable.

Validation uses the actual release with synthetic HTTP data. One prerequisite runtime is held for 45 seconds, beyond the original installer windows, then inserted intact. The V337 baseline is required to visibly lack its consumers; the candidate must recover without reloading. A later deliberate reload checks that the coordinator targets the new document. This fault injection demonstrates the late-prerequisite failure class; it does not establish the exact network cause of an earlier private incident.

Independent checks cover finite attempts, one shared observer, disconnection, duplicate registration, document replacement and no polling/data operations. The existing actual-asset browser contract checks Desktop and two mobile viewports, monthly switching and failures, bank reconciliation, actions, card details, preserved financial values and a 365-day clipboard export. Synthetic viewports do not certify a physical phone or all production timing conditions.

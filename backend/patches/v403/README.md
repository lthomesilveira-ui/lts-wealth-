# V403: bounded Open Finance source writes and backup exclusion

V401 already validates the complete 33-table backup manifest and bounds the scheduled connection to90seconds. V402 already reconciles complete, verified Cofrinho investment cohorts by source date. This correction preserves both implementations and all original observation rows.

The two ingestion entry points previously wrote an observation and a full staging upsert for every repeated record. V403 retains every new or materially changed raw/normalized/reconciliation value, every stale payload, and every balance/investment/loan cohort. It does not repeat unchanged transaction, card, invoice or account payloads. Unknown resource types remain fully recorded. Provider collection freshness alone is not a changed transaction.

Staging consultation timestamps and run identity remain current. Their updates are grouped once per incoming batch and reuse original financial payloads. An exact transient per-record receipt supports overlapping batch retries and detects changed retry payloads while the run is open. On completion it becomes coverage counts and an independently reproducible SHA256, without retaining another copy of the received financial payloads. Interrupted runs retain their receipts. Received and normalized counts still reflect the full input, rather than only the retained observations. Old run rows and observation IDs remain valid.

The existing daily backup moves from03:15 to03:35 SãoPaulo, with bounded retry opportunities at03:40,03:50 and03:55. The hourly bank schedule remains atminute15. After the first successful daily capture, subsequent attempts read stored metadata only. A shared/exclusive transaction lock plus active/queued-run checks prevent the scheduled backup from overlapping ingestion. A deferred capture is logged and remains visibly absent until a later attempt succeeds. The V401 writer,90second deadline, manifest, old bundles and all other schedules are preserved.

Apply `write_policy.sql`, `backup_exclusion.sql`, `backup_critical_sources.sql` and `backup_data_only.sql` in one atomic migration after the native tests pass and while no bank collection is active. Deployment holds the existing bank begin locks. Changed predecessors and partial upgrades are rejected, and replay is supported. No historical deletion, retention change, financial promotion, paid upgrade, source-date rewrite or public interface change is included.

The modern profile also gains the owner-scoped resource mapping and the last successful position cohort per bank/civil day, together with every referenced run. The35-dataset validator delegates historical29/31/33profiles to the unchanged V401 validator. Existing stored archives retain their hashes. This adds the source evidence needed by the V402 daily reader; it explicitly does not represent the complete multi-gigabyte observation archive, schema/auth or Storage binaries.

The scheduled command uses a repeatable-read transaction and retains the90second statement deadline. Its original legacy data arrays are copied through a separate private exporter that does not call `lts_refresh_runtime_gate` or re-run the operational engine QA suite. The original diagnostic/export APIs remain unchanged. New bundle metadata explicitly states that runtime QA was not executed, records capture kind and isolation, and uses row counts, hashes and restoration as data-integrity evidence. Manual validation captures must be labelled separately from scheduled captures and must not rewrite the failed02November cron record.

Validation includes exact retries, incomplete coverage, changes despite unchanged hashes, stale payloads, unchanged consultation clocks, complete V402 Cofrinho cohorts, original financial/source conservation, concurrent sessions and an independent PostgreSQL database restore. Synthetic CI never contains private production rows. Production verification must separately record a natural completed collection, retained input/storage counts, source-vector parity and backup outcomes. A sample restore is not a full independentDB/Storage/Auth disaster-recovery certificate.

# Restricted resource consistency

Reuse the existing owner-authorized daily FGTS scenario in product summaries and liquidity ladders. Merge only FGTS fields from the existing adjustment transform: never apply its brokerage deduction twice. Current documentary FGTS remains unavailable after a withdrawal until a later source is provided. A planning estimate is a separate field, not a documentary balance. Known wealth subtotals exclude an unknown component, and identify that limitation.

Native PostgreSQL tests use invented data only. They verify cash and brokerage preservation, daily accrual, immutable history/events, unknown versus documented zero, later statements, idempotence, pensions and private privileges. They do not certify a private HTTP session or physical device.

Integration rewiring requires exact predecessor guards, unchanged function privileges and execution settings, an idle existing worker, source-preservation evidence and a natural refresh before declaring the change installed. No financial transactions, source documents, schedules or published interface assets are changed. Do not expose user data in this public repository.

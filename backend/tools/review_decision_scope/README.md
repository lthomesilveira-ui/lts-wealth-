# Bounded bank classification decisions

A real existing classification request timed out and rolled back. The writer
validated the entire occurrence month twice and consulted the expensive historical
category options before the owner's active catalog. A read-only source-day sample
returned the exact pending bank occurrence in about 1.34 seconds.

This function-only correction narrows pending/resolution validation to the exact
civil date for a posted, undeleted checking-account transaction. Card, monthly,
legacy and incomplete observations retain the original month-to-current-day scope.
The category allowlist is unchanged, with its cheap active-catalog and cached
branches first. Authorization, target checks, post-write resolution, rollback,
audit, timeouts and all financial source rows remain unchanged.

The installer and rollback reject concurrent definition changes. Native isolated
PostgreSQL tests exercise the actual original and patched function bodies against
invented data. No production identities or credentials enter CI. Synthetic tests
are not proof of actual authenticated completion; the existing app action must
then be repeated and observed once after confirming the failed transaction left
no decision. This work does not promote or modify the V448 chart candidate.
